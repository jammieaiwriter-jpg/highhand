# 93H 自動結案規則（2026-10-07 玲嬅定，所有班次共用）

> 正本在 `進度追蹤/自動結案規則.md`；建置時同步到 highhand repo `tools/auto_close_rules.md`，雲端記帳、
> 桌機回報備援、週三會議三條線都讀這份。改規則只改正本，跑一次上傳 bat 或 `rebuild` 雲端就跟上。
>
> 目的：玲嬅久久看一次、不會逐題回覆。**系統有證據就自己結案；沒證據就標記，不發問；
> 只把真正要她拍板的事留給她。**

## 一、有證據 → 直接改狀態（不發問）

每次改狀態都把原值寫進備註「(原狀態:…)」並註明來源日期，玲嬅事後可對照。

| 證據（回報／日誌／會議） | 動作 |
|---|---|
| 明講「完成／已完成／完工／已拆除／已安裝完成／100%／驗收OK」，且能以「廠商＋工項核心詞」唯一對到追蹤列 | 狀態改「已完成」（缺失改善、四表、門禁、行政時程「完成」欄、廠商協調「狀態」欄同理） |
| 料「已到／已進場／已到貨」 | 進料追蹤「實際到料」填 M/D |
| 行政時程的事項回覆「已回報／已提出／已交／已開會」 | 「完成」欄填「M/D已…」 |
| 新日期（延期、提前、改期）出現在較新的資料 | **最新的贏**：直接改日期，原日期進備註；不再問「哪個對」 |
| 同一事項多個來源日期打架、但都在同一份會議紀錄 | 會議內文＞表格＞甘特圖判讀；採用後備註「⚠️會議內部不一致:…」 |
| 範圍型項目回報做到某樓層 | 「進度」欄推進 |

對不到唯一列（命中 0 列或多列）→ 不寫狀態，在當次 Telegram 摘要「未能對應」段列一行即可，**不開待確認題**。

## 二、沒證據 → 標記，不刪、不猜、不發問

- **出工預核過期空白**（預定日已過 2 天、實際出工仍空白、同廠商當天也沒有其他回報列）：
  體檢工具自動填「未出工?(無回報,M/D自動標記)」→ 該列移到儀表板「改期待重排」區；
  之後該工班只要再出工，改期列依規則 3 自動消失。不再開「有來嗎？」題目。
- **過期且沒有新日期的追蹤項**（例：MF 欄杆原 9/27）：保留原日期，備註加「⚠️…已過期,待重排」。
  **絕不清空日期、絕不刪列**（玲嬅 10/7 定）。
- **廠商別不明**：不發問。廠商欄寫「工項名(廠商未載)」；`find` 查得到同工項的前例廠商時可寫該廠商並備註「依前例判定」。
- **不知道是不是同一項**（例：4F 門框是否同批）：當新列記錄，備註寫「可能同 rN」，不發問。

## 三、只有這三類才開待確認題（每題要能用一個字或一個日期回答）

1. **里程碑**日期或完成與否（🔴 開頭）。
2. **費用歸屬**（誰付、扣誰）。
3. **公司決策**（選哪家、要不要做）——同時寫進「待裁決」分頁。

題目格式：一句話＋選項，例
`pending add --q "🔴 1F 門禁 10/16 能完成嗎？" --options "能|延到＿＿|不知" --ref "門禁追蹤 r9"`。
選項會自動變成 Telegram 與儀表板「👆待你確認」的按鈕（後端每 5 分鐘推送新題）；含「＿＿」的選項不出按鈕、請玲嬅手打。不寫背景長文，背景放 ref 欄。玲嬅按了按鈕＝狀態「已回覆」，下一班次照常落實並 close。

## 四、待確認題的期限

- 開題 **14 天**沒回 → 體檢工具自動改狀態「逾期關閉」，回覆欄註明「14天未回覆自動關閉」。
  相關資料維持原樣（不因關閉而改動）；週三會議班次在摘要列出「上週逾期關閉題」供會議順便問。
- 玲嬅任何時候回覆（TG 帶編號或填 Sheet），已關閉的題仍照常落實。

## 五、粗工必入「粗工打石」

出工預核有毅文／粗工／打石（承達等）出工時，**同一批變更單**必須在「粗工打石」分頁補一列
（日期｜工種｜廠商｜人數｜工作內容｜費用歸屬｜金額｜備註；歸屬不明寫「公司(待確認)」）。
append 帶 `unless_exists`（日期＋廠商）。9/25～10/3 曾整段漏記，造成週對帳不符。

## 六、里程碑（2026-10-14 起正本在雲端 Sheet「里程碑」分頁）

欄位：名稱｜日期｜說明｜已完成日｜樹狀分組。儀表板頂部倒數與里程碑樹都讀這頁（讀不到才退回產生器內建值）。

- **改「日期」只有一種情況：玲嬅回覆了 🔴 里程碑題**（待確認狀態＝已回覆，來源 TG按鈕／TG回覆／儀表板／Sheet）。
  照她的答案改該列「日期」，「說明」欄接一段「玲嬅M/D回覆Qxxxx:改X(原Y)」，然後 `pending close`。
  答案是「維持」→ 日期不動，只在說明欄記「M/D回覆Qxxxx:維持」。答案是「延到＿＿」→ 寫她打的日期。
- 會議、日誌、柏銘表出現新的里程碑日期 → **不改**，開 🔴 題（選項例：「改M/D|維持原日期|延到＿＿」）。
- **「已完成日」可依證據填**：回報或會議明講該里程碑事項已完成（例「拆架完成」「已取得使照」）→ 填完成日、說明欄註來源。
  不確定是否算完成 → 開 🔴 題問「XX 算完成了嗎？ 是|否」。
- 日期一律寫 `0115/10/12` 這種前置 0 的民國字串。不刪列、不改「名稱」與「樹狀分組」（要調整結構請玲嬅在對話中處理）。

## 七、⭐ 玲嬅重點追蹤項目（2026-11-02 定）

1. **台電拆除臨時電桶**——送審變更「台電拆除臨時電桶(⭐重點)」列。
2. **消防變更**——送審變更「消防變更設計」列。

- 回報／日誌／會議只要提到這兩件（含：台電、工管科、臨時電、電桶、路證、電桿；消防變更、技師、設備師、圖審、送件、安鼎計算），
  **一律寫進上述那一列**（送件日／預計核准／實際核准欄＋備註接「M/D來源:內容」），不要只散在出工預核或行政時程。
- 每次推 Telegram 摘要，**第一段固定**列兩行（就算今天沒消息也列，寫「今日無新進度，現況：…」）：
  `⭐台電拆臨時電桶：<最新一句>（目標 <預計核准欄>）`
  `⭐消防變更：<最新一句>（目標 <預計核准欄>）`
- 送件、核准、拆除完成這類**狀態改變**當天，在摘要該行前加 🔔。目標日過了仍未完成 → 該行加 🔴。
- **臨時電桶「拆完」的認定（玲嬅 11/4 定）**：要**兩段都完成**才算——①台電工一課（#3513 張先生）拆電器，案號 8210838；
  ②之後工二課（#3555 朱先生）拆管路，案號 9210066。只完成一段→送件欄寫進度、實際核准欄留空。
  原文含「(?)」或語意不明（例 11/4 會議「11/2 追蹤工一課進度(?)…-->完成」曾被誤判為已拆）→ **不填完成**，改開 🔴 題問「臨時電桶已拆完了嗎？ 已拆完|只拆電器|還沒」。

## 八、會勘紀錄一律匯入「缺失改善」（2026-11-12 玲嬅定）

來源包含：回報收件匣的「會勘」(`?today=1` 的 sv)、TG 轉送的會勘／巡視內容、公司雲端會勘資料夾（skill 93h-inspection）、會議紀錄裡的「總經理看現場／巡視」交辦。

- **每一點都寫一列到「缺失改善」**（不論是缺失、追加、要報價或要排工）：
  發現日＝會勘日｜缺失內容＝交辦內容（一句話）｜位置｜責任廠商（不明就依前例或留空，不發問）｜改善方式｜預計完成｜狀態＝待處理｜
  備註**開頭固定** `【會勘M/D｜巡視人】`（例 `【會勘11/10｜總經理】`），後接原文重點。儀表板缺失追蹤區會自動掛「🔍會勘」標籤。
- 「工地會勘紀錄」工具（meeting-records）按「回傳公司」送來的會勘：會勘分頁的**日期欄＝回傳當天**，真正的會勘日在「陪同」欄／原文的「會勘日YYYY-MM-DD」，**發現日與【會勘M/D】一律用會勘日**；狀態「未結案／現場新增」→待處理，「已確認」→已決議（仍要建列）。
- 先 `find` 查重：同一點已在缺失改善 → 更新原列（備註接「M/D會勘再提:…」），不另起新列。
- 需要另外作業的，**仍在缺失改善列為主**，另一分頁只放作業用的那一面並互註列號：
  有日期要工班進場 → 出工預核加一列（備註「見缺失改善 rN」）；要報價／發包 → 發包與工作事項加一列（同樣互註）；要列入規約 → 規約待查。
- 費用（追減、補貼、扣款、歸屬）寫在缺失改善的「責任廠商／備註」；歸屬不明照§三開 費用歸屬題。
- 會勘的點完成（回報或會議明講）→ 依§一 直接改「已完成」，備註保留【會勘…】開頭。


## 九、晚報答「明天」→ 一律建明日出工列（2026-11-12 玲嬅定）

Grok bot 收到早報會拿 plan.json 的 `today`（＝出工預核今日列）即時比對「應到沒到」，所以**工地已承諾明天會來的工班都要有明日列**，不能只寫在備註。

- 晚報／工作日誌**任何一題**的回覆含「明天／明日／明早＋進場、施作、繼續、完成、更換、補」等，且看得出是哪個工班（用回報 Sheet「廠商對照」分頁的別名對應）→ 在出工預核建**明日**一列：
  日期＝明天｜廠商/工班＝「廠商(工項)」｜預定工作＝該題事項｜來源＝`TG轉送-<寄件人>(M/D工作日誌#N)`｜實際出工＝空白｜備註＝`M/D工作日誌#N回覆:明天…`。
- 「安裝中，明天繼續」「未完成明天繼續」也算（續做中的工班）。
- 照常查重：同廠商明日已有列（含「明日派工」那題建的）→ 更新那列備註，不另起新列；append 帶 `unless_exists`（日期＋廠商名前2~3字）。
- 原本的列（例如舊預定日、改期過的列）照§一「最新的贏」更新日期或標「已重排」，避免同一件事同時掛在兩天。
- 只答「明天聯繫／明天確認／明天詢問」的不建出工列（不是工班進場），照舊寫備註。
